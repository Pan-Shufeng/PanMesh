# PanMesh

让你选定的 AI 窗口组成一个项目组。你留在主对话里说明目标、项目和模型，主 AI 拆任务、通知执行窗口、收回成果并验收。你还可以选中一段值得复盘的对话，保留双方原话，把其中有用的纠正慢慢整理成自己的工作方法。

## 为什么组合不同 AI

- **省贵模型的额度。** 让强模型负责拆解和疑难验收，把批量整理、初稿和独立核查交给另一份额度合适的模型。简单任务直接用一个窗口即可。
- **省重复交代的上下文。** 执行方拿到本轮目标、必要材料、做法版本和验收条件。退回时只补有问题的项，接手时沿任务编号查已有成果。多加一个模型仍会产生用量。
- **额度或优惠变了，可以换组合。** 针对不同项目选择执行客户端、模型和派工方式，继续沿用同一套任务记录。订阅、网关或客户端自身的审批和计费规则仍然适用。
- **留下对话供自己分析。** 你选什么才收什么。保留可见原话、角色、顺序和缺口，再分别写案例和做法。在 Obsidian 里可以从结论回到那句纠正，也可以改出新版，观察它在下一道题上是否有效。

## 从两句话开始

**首次安装**，把 [安装 agent 说明](INSTALL-AGENT.md) 给能够操作本机的 WorkBuddy、GPT、Claude 或其他助手，并告诉它：

> 把 PanMesh 装在 D:\PanMesh。项目是 D:\论文整理，接入 Codex 和 Cursor，都用协作模式。这个聊天先当我的记忆系统打理 agent，做完告诉我怎么交接给另一个聊天。

**日常协作**，在想当负责人的主对话中提供 [协作执行说明](COLLABORATE.md)，再说：

> 你主负责这篇报告。让 Cursor 的论文整理项目用我指定的模型核对引用，你自己检查结论。帮我提醒它领取，回来逐项验收。这次要保存哪段对话由我选。

主窗口需要能访问本机服务，并有操作目标窗口或受支持执行端的渠道。纯网页聊天可以读说明；与本机任务簿通信需要另有连接。安装助手可自由选择，执行适配器的支持范围见下表。

## 系统怎样工作

| 组成 | 技术与职责 |
| --- | --- |
| 项目接口 | Python 3.11、MCP 官方 Python SDK、本机 stdio。每个客户端连接绑定一个项目、角色与权限模式。 |
| 共享记忆 | SQLite 保存版本、授权、来源和试用记录。imports/ 保存选定原件，vault/ 中的 Markdown 可由 Obsidian 直接阅读和编辑。共享一条做法摘要可以单独授权。 |
| 协作任务簿 | SQLite 记录派工、领取、分项提交、验收、返工及用量。重复操作按请求编号去重；发送结果未知时先核对回执。 |
| 执行与通知 | 已打开的项目聊天可主动领取；主 AI 借助自身桌面能力发送短提醒。支持的 CLI 可由本机协调器后台启动，在主窗口关闭后保存回报。 |

**capture（只采集）**允许追加选中的材料。**collab（协作）**还可以读取获准资料、提议修改、领取和回报任务。按项目和客户端分别配置；连接 MCP 与采集整段聊天是两个独立选择。同一系统用户的直接读盘权限由操作系统控制。

## 可以定制什么

现有入口包括 Codex、Cursor、Claude Code，以及 Claude 桌面 Code 标签中的项目会话。Cursor 使用项目 MCP 领取，桌面 Claude 可使用已配置的 Gateway。后台 CLI 路径单独核对账号条件。不能从当前通道指定模型时，主 AI 应报告限制。

换外壳时，从项目 MCP 或任务簿的领取接口接入；换模型调用工具时，在 connectors/ 中适配启动、会话标识、回执及用量，再向 routing.py 登记路由。你也可以调整分工提示词、验收标准、做法模板、通知方式和分享范围。任务簿字段及恢复约定见 [接口文档](ledger_api.md)。
