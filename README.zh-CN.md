# PanMesh

[English](README.md) · 简体中文

模型厂商政策说变就变，降智、限流、改价、风控，额度和优惠规则一天一个样。加上顶级模型轮流坐庄、旗舰 Token 太贵，日常只能“强模型做关键判断，把批量执行交给更便宜的模型”混搭着用。而好工具又往往只适配原生或热门客户端。干到一半的任务，随时可能被迫迁移。

换工具本身还能接受，最折磨人的是记忆割裂。人工交接上下文太累、怕遗漏，更不想一遍遍重复交代前情。

所以我写了 PanMesh，一个跨平台的 AI 协作记忆库，也许是你的新选择。你可以在熟悉的主对话里指挥其他窗口一起做事，也可以自己选出值得留下的原话和做法，留给以后复盘和复用。

让你选定的 AI 窗口组成一个项目组。你留在主对话里说明目标、项目和模型，主 AI 拆任务、通知执行窗口、收回成果并验收。你还可以选中一段值得复盘的对话，保留双方原话，把其中有用的纠正慢慢整理成自己的工作方法。

## 优势

- **让已有的 AI 窗口协作。** 在主对话里指定项目和执行窗口，主 AI 拆任务、通知领取、收回结果并验收。你可以留在一个窗口，省去来回传任务编号和结果的步骤。
- **省去重复交代上下文。** 换窗口或下次接着做时，执行方可以读取项目里已获准的做法摘要，再结合本轮材料和验收条件开工。你纠正过的引用规则，下次核对时就能直接沿用。
- **省贵模型的额度。** 让强推理模型拆解难题、裁定争议，把批量提取和格式整理交给额度充足的模型。贵模型可以集中检查影响结论的部分。
- **额度或优惠政策变了，可以换组合。** 订阅额度调整、另一家推出优惠，或新模型更擅长某项任务时，都可以单独更换那一步的执行方，继续沿用项目已有的做法和验收记录。
- **跨客户端用上各自生态。** 某个 Skill 在 Claude Code 里用得最顺，就把那一步派给 Claude Code。如果核对来源的 MCP 已经配在 Cursor 里，就让 Cursor 取证，再由主 AI 验收。
- **摘要、案例、原始记录分层可编辑记忆。** 你可以修改做法摘要，在案例中补充判断理由，并沿链接回看选中对话的原话和顺序。给其他窗口分享摘要时，原始记录可以留在本项目。
- **留下对话供自己分析。** 选几段自己的对话放在一起复盘：哪些要求总要到返工时才想起？哪种提问让模型一次就给出了可核查的证据？比较当时的原话和结果，可以看清自己的使用习惯，把有效的方法带到下个项目。

## 快速开始

**首次安装**，把 [安装 agent 说明](INSTALL-AGENT.zh-CN.md) 给能够操作本机的 WorkBuddy、GPT、Claude 或其他助手，并告诉它：

> 把 PanMesh 装在 D:\PanMesh。项目是 D:\论文整理，接入 Codex 和 Cursor，都用协作模式。这个聊天先当我的记忆系统打理 agent，做完告诉我怎么交接给另一个聊天。

**日常协作**，在想当负责人的主对话中提供 [协作执行说明](COLLABORATE.zh-CN.md)，再说：

> 你主负责这篇报告。让 Cursor 的论文整理项目用我指定的模型核对引用，你自己检查结论。帮我提醒它领取，回来逐项验收。这次要保存哪段对话由我选。

主窗口需要能访问本机服务，并有操作目标窗口或受支持执行端的渠道。纯网页聊天可以读说明；与本机任务簿通信需要另有连接。安装助手可自由选择，已测客户端见下文。

## 在一个主对话里带多个 AI 工作

如果你习惯在 GPT 里说“你主负责，拆任务派给其他窗口，最后你验收”，跨客户端也可以沿用这句话。选一个能访问本机项目、能通知目标窗口的 GPT 主对话（例如 Codex），提供协作说明，然后说：

> 你主负责这份报告。让 Papers 项目里的 Cursor 用我选的模型逐条核对引用，让 Claude Code 独立检查结论。你汇总两边的证据，只把有问题的项退回补做，最后给我验收结果。等我选好再保存对话。

主 AI 把两个子任务和各自的验收条件写进任务簿，按已登记的路由提醒现有窗口领取，或启动受支持的后台执行端。两个窗口分别提交成果和未决项，主 AI 对照原文验收。可用通知渠道已配置时，你只需留在主对话；客户端要求批准或指定模型不可用时，主 AI 告诉你具体卡在哪一步。

## 客户端支持

项目已测试支持 **Codex、Claude Code、Cursor、Antigravity、DSH 和 WorkBuddy**。各客户端可用的接入方式、模型选择、窗口通知和后台执行能力取决于其配置及适配器。**Hermes** 等客户端列入后续测试计划。

## 系统怎样工作

| 组成 | 技术与职责 |
| --- | --- |
| 项目接口 | Python 3.11、MCP 官方 Python SDK、本机 stdio。每个客户端连接绑定一个项目、角色与权限模式。 |
| 共享记忆 | SQLite 保存版本、授权、来源和试用记录。imports/ 保存选定原件，vault/ 中的 Markdown 可由 Obsidian 直接阅读和编辑。共享一条做法摘要可以单独授权。 |
| 协作任务簿 | SQLite 记录派工、领取、分项提交、验收、返工及用量。重复操作按请求编号去重；发送结果未知时先核对回执。 |
| 执行与通知 | 已打开的项目聊天可主动领取；主 AI 借助自身桌面能力发送短提醒。支持的 CLI 可由本机协调器后台启动，在主窗口关闭后保存回报。 |

**记忆库支持多项目并行，各项目的记忆默认隔离。** 多个项目可以同时使用同一套 PanMesh。每个 MCP 连接绑定自己的项目和角色，即使两个项目使用相同的角色名和来源编号，各自的对话和任务也会分别保存。需要跨项目复用经验时，可以只授权对方读取某条做法的摘要，原始对话仍由来源项目控制。[三项目并行测试](tests/test_project_mcp.py)验证了每个项目都能读回自己的记录，通过 MCP 读取另外两个项目的记录会被拒绝。

## 每个窗口选什么模式？

| 模式 | 这个窗口能做什么 | 什么时候选 |
| --- | --- | --- |
| 只采集（capture） | 把你指定的原话、片段或材料位置追加到本项目，取得收据。此连接没有检索和派工工具。 | 想留下一段有价值的讨论，供以后复盘。 |
| 协作（collab） | 检索获准的做法摘要，按权限回看来源，提出修订，或在任务簿里派工、领取、回报和验收。 | 希望这个窗口带队、执行任务，或复用已认可的经验。 |

模式按项目和客户端分别配置。例如同一项目可以让 Codex 和 Cursor 协作，让另一个只做访谈记录的窗口只采集。接入 MCP 后，原生记忆仍由客户端设置管理。PanMesh 只保存你选中的个人材料；另行登记的自动采集也有明确的会话范围。MCP 权限管的是通过服务的访问，直接读盘仍受操作系统权限控制。

## 一段聊天怎样变成下次能用的做法？

假设 AI 把摘要中的数字当成了原文数据。你可以先说：“只保存从我指出来源问题到你交付修正版的几轮原话。”以后再请协作窗口把初答、纠正理由和被接受的结果整理成案例，链接回对应轮次。你可以另行认可一条做法，例如“报告数字前先核对原文表格”。下次派工只给执行方这版摘要；需要看原话时另行授权。即使后来改了做法，旧任务仍可追溯到当时采用的版本。

## 可以定制什么

现有入口包括 Codex、Cursor、Claude Code，以及 Claude 桌面 Code 标签中的项目会话。Cursor 使用项目 MCP 领取，桌面 Claude 可使用已配置的 Gateway。后台 CLI 路径单独核对账号条件。不能从当前通道指定模型时，主 AI 应报告限制。

换外壳时，从项目 MCP 或任务簿的领取接口接入；换模型调用工具时，在 connectors/ 中适配启动、会话标识、回执及用量，再向 routing.py 登记路由。你也可以调整分工提示词、验收标准、做法模板、通知方式和分享范围。任务簿字段及恢复约定见 [接口文档](ledger_api.md)。
